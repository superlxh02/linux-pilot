# 管理员账号与用户管理

首次部署请在仓库根目录运行：

```bash
./web/scripts/init-env.sh
docker compose up -d --build
```

内置管理员使用一个固定的初始凭据：

```text
用户名：admin
初始密码：admin-5a2c966a29f39ec1248ae6ba480ae765158d26fef745e139
```

登录时请使用半角英文 `admin`；密码实际值为下方 `.env` 中的 `ADMIN_PASSWORD`。初始化脚本只为数据库、Worker 等其他密钥生成随机值，管理员初始密码保持上述固定值。查看当前部署使用的密码：

```bash
grep '^ADMIN_PASSWORD=' .env
```

如果从此前的随机管理员密码版本升级，已有 `.env` 中的 `ADMIN_PASSWORD` 会覆盖固定初始值。将它改为上面的固定密码，再重新创建后端容器；后端会更新现有 `admin` 账号的密码哈希并撤销旧会话。若希望正式部署使用自己的密码，也只需修改这一项并重启后端。

在登录页输入用户名 `admin` 和当前配置的密码。后端只在数据库保存 Argon2id 密码哈希；当 `ADMIN_PASSWORD` 与现有密码不同时，启动时会更新哈希并撤销管理员旧会话。**固定初始密码公开可见，`PO_MODE=production` 时必须在 `.env` 中替换为自己的长密码，否则后端会拒绝启动。**不要把正式部署的 `.env` 或密码截图提交到 Git。

管理员可以在“用户管理”页面查看账号、注册和最近登录时间、分配 `只读`、`操作员` 或 `管理员` 角色，并查看所选用户最近 100 条登录、登出、权限变更、告警操作与性能剖析记录。内置 `admin` 的角色不可在页面修改。角色变更由后端再次校验管理员会话，立即对现有会话生效；原来的静态操作令牌不能访问管理接口。

历史版本的审计行没有操作者信息，无法可靠归属到某个账号，因此不会错误地展示在任何人的个人操作记录中。需要调查全局旧记录时可由运维人员在数据库中查询 `audit_events`。
