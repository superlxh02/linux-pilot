CAPABILITIES

从症状到原因，工具都在这里。

保持数据口径清晰，让性能排查有依据，也给后续自动分析留出边界。

⌁
01 / METRICS

主机指标

CPU、内存、PSI、磁盘、文件系统、网络、进程与 cgroup，按分类查询历史和实时趋势。

◎
02 / EBPF

内核信号

观察 TCP 连接与重传、块请求延迟、调度等待。探针不可用时保留基础采集并标明能力。

▥
03 / PERF

CPU 剖析

按需触发 perf 采样，查看折叠栈和火焰图，追踪 CPU 时间花在了哪里。

◈
04 / SCORING

场景评分

通用、CPU、应用 I/O、存储与网络五种场景，展示维度分、覆盖率和扣分证据。

⇄
05 / DELIVERY

可靠传输

Worker 先写本地缓冲，再通过双向 gRPC 流发送。中心端持久化后 ACK，断线恢复可回放。

◇
06 / ACCESS

账号与权限

邮箱验证、密码登录与可配置的 GitHub、Google OAuth；只读和操作员角色分开。

SIGNAL COVERAGE

把系统状态拆成可读的信号。

每项指标都附带单位、来源和诊断含义。缺失数据以缺失呈现，不会被写成零。

01

CPU 与调度

使用率、负载、steal、运行队列、上下文切换、调度等待

02

内存与压力

可用内存、缓存、缺页、swap、PSI 等待时间

03

存储与 I/O

设备吞吐、队列、延迟、文件系统容量和 inode

04

网络与 TCP

带宽、丢包、连接状态、eBPF 重传和连接耗时

05

进程与容器

进程 Top N、cgroup CPU/内存限制与使用情况

06

按需性能分析

perf 调用栈、采样数、任务状态与火焰图

GET STARTED

先启动 Web，
再接入 Linux 主机。

Web Compose 只包含前端、后端和 PostgreSQL。邮箱联调可叠加本地 Mailpit；Worker 使用独立脚本部署到目标主机。

查看源码与完整文档 ↗
01启动 Web
cp .env.example .env
docker compose -f compose.yaml -f web/compose.dev.yaml up -d --build
先在 .env 中设置数据库密码、Worker 令牌和验证码密钥；生产使用真实 SMTP 且不叠加 Mailpit。
02启动 Worker
cd worker
cp .env.example .env
./manage.sh start
在目标 Linux 主机填写中心地址与相同的 Worker 令牌。
